# 範囲: regied がやらないこと

regied は意図的に小さく保つ（[ADR 0001](adr/0001-why-build-our-own.md)）。
ここに挙げたものはどれも**意図的に落としたもの**であって、埋めるべき穴ではない。
必要になったときは、黙って足すのではなく新しい決定として記録すること。

## 実装しないもの

### UPnP IGD と NAT-PMP

LAN 側の端末から動的にポートマッピングを要求する仕組みは持たない。

これが欲しくなる典型はゲーム機が NAT タイプの制限を報告する場面である。
そこで実際に効いているのは NAT のマッピング挙動——宛先を変えたときに外部ポートが
変わらないかどうか——であり、Linux の `conntrack` NAT は既定でこれを満たす。
素の nftables masquerade で緩い側の NAT タイプ相当になり、大半のタイトルはこれで繋がる。

UPnP が効くのはそこから 1 段だけであり、LAN からの認証なしのマッピング要求を
受け付けるデーモンを 1 つ増やす見返りとしては小さい。
特定の端末が別の経路を必要とするなら、ポリシールーティングの対象レンジに
そのアドレスを足せばよく、それは 1 行の変更である。

本当に必要になったら `miniupnpd` を別プロセスで動かせる。regied 本体に持たせる必然性はない。

### VPN の終端

IPsec、L2TP、WireGuard、Tailscale はいずれも持たない。
上位回線そのものに要る IPv4 over IPv6 トンネル以外のトンネルを regied は終端しない。

終端するものが無いのにファイアウォールの穴だけが開いている設定は、
どちらも無い状態より悪い。したがって穴の側もモデル化しない。

### 動的ルーティング

BGP も OSPF も RIP も持たない。動的ルーティングが要るなら FRR / BIRD / GoBGP の仕事である
（[ADR 0008](adr/0008-delegate-to-existing-implementations.md)）。
そのとき regied の役目は邪魔をしないことで、自分が入れた経路だけを消すので
学習経路は残る（[ADR 0009](adr/0009-ownership-boundary.md)）。

### オーバーレイネットワーク

VXLAN も VRF も持たない。「1 台のホスト、1 本の上位回線」とは違う種類の構成に属する。

### マルチノード、HA、クラウド連携

regied は **1 台**のノードを見るデーモンである。クラスタリング、リーダー選出、
フェイルオーバー、クラウド事業者 API との連携はいずれも持たない。

**配布は明確に範囲外である。** 設定ファイルがどうやってノードに届くかは別の仕組みの
問題である（構成管理ツール、Git ベースの配信、イメージのビルド）。
ここを曖昧にすると、1 ノードのデーモンが多ノード管理へ滑り落ちる。

### Web コンソール

GUI は持たず、リソースの書き込み API も作らない。
設定のソースオブトゥルースは YAML ファイル 1 つだけである。
HTTP API は読み取り中心（適用状態、回線状態、リース、conntrack のサマリ、health）で、
書き込み系を足すとしても `reload` / `apply`（dry-run 付き）までに留める。
リソースの CRUD は作らない。

設定を変えられる GUI は宣言的モデルに 2 つ目のソースオブトゥルースを作り、両者はずれていく。

### トラフィックの分類と分析

DPI（深層パケット解析）もフローのエクスポートも、ベンダーのサービスへのテレメトリ送信も持たない。

### パッケージ管理とホストの構築

regied はパッケージを入れず、リポジトリを管理せず、ホストを構築しない。
委譲先の道具（systemd-networkd、dnsmasq、pppd、nftables）は既にあるものとして扱う。

### ログインアカウントとリモートアクセス

ユーザーアカウント、パスワードハッシュ、SSH 公開鍵、SSH デーモンの設定は OS 側に残す。
regied はこれらをモデル化しないし、設定に現れることもない。

## OS が持つのでモデル化しないもの

ベンダーのルーター OS が「設定」に含めているもののうち、
汎用の Linux では既に別の何かが持っているものがある。regied はそれを取り上げない。

| 領域 | 持ち主 |
|---|---|
| システムログ | journald / rsyslog |
| 時刻同期のクライアント | システムの NTP クライアント |
| ログインアカウントと SSH | OS |
| パッケージリポジトリ | ディストリビューションのパッケージ管理 |
| ルーター以外のホストの base ネットワーク | netplan など、既に持っているもの |

ホスト名・タイムゾーン・NTP サーバーは境界に近い。
OS の仕組みより宣言したほうが有用だと分かればモデル化するかもしれないが、
先に作る 7 領域には含まれていない。

## ハードウェアに依存するので保留するもの

ベンダーのルーターには設定可能な内蔵スイッチを持つものがある
（ポートの所属、VLAN の扱い、ハードウェアオフロード）。
同等のものが手元のボードで使えるかどうかは、そのボードのカーネル DSA 対応に依存する。

regied は代わりに Linux ブリッジをモデル化する。
ハードウェアスイッチの設定は、対応が確認できた具体的なボードが出てくるまで保留する。
そのときは推測ではなく要件として起こす。

## 意図的に挙動を変えるもの

設定の移植は設定の複写ではない。省略ではなく改善にあたる変更が 2 つあるので、名前を付けておく。

**TCP MSS の clamp は、MTU が下がるすべての経路に掛ける。**
特定のインターフェース種別だけではない。LAN より MTU の低いトンネルは PPPoE と同じくらい
clamp を必要とし、Path MTU Discovery だけに頼るのは脆い。

**ICMP redirect は送らない。** ベンダーの既定で有効になっていることは、
それを引き継ぐ理由にならない。単一セグメントの LAN では redirect に果たす役目がない。
