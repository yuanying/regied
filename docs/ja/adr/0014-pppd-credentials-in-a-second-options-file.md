# ADR 0014: pppd への資格情報は 2 つ目のオプションファイルで渡す

- 状態: 決定（2026-09-02）

## 背景

PPPoE のセッションには、regied が書き留めてはならない値が 2 つ要る。アカウント名と
パスワードである。[ADR 0003](0003-secrets-out-of-configuration.md) は、スキーマは
それらが入ったファイルの**パスだけ**を持ち、regied が診断のために出すものには
どちらも現れない、と決めている。`--dry-run` の出力にも、差分にも、ログの 1 行にも出ない。
`PPPoESession.userIDFile` と `passwordFile` は利用者が書く側である。この記録が答えるのは、
その先にある値を regied がどう扱うかである。

pppd には資格情報の置き場所が 3 つあり、そのどれを選ぶかは、置き場所以外のことも同時に決める。

**ppp 自身の secrets ファイル。** `/etc/ppp/pap-secrets` と `/etc/ppp/chap-secrets` は、
ppp がパスワードを置く場所として用意している。どちらも ppp 自身が置く固定パスであり、
そのホストで ppp を使う他のものと共有される。つまりそこを書き換えるのは、
[ADR 0009](0009-ownership-boundary.md) が禁じた「自分が作っていないファイルを書き換える」
そのものである。しかも、それで両方が収まるわけでもない。pppd は `user` オプションで
与えられた名前に一致するエントリを選ぶ。`user` は他と変わらないオプションなので、
アカウント名は結局オプションファイルに平文で書くことになる。**人に見せることが目的の
ファイル**に、である。

**オプションファイル 1 つにまとめる（参照実装のやり方）。** `hack/netns/router/reference.sh`
は `umask 077` のもとで、すべてのオプションと資格情報の両方を 1 つのファイルに書く。
それで動くし、手書きのスクリプトとしては正しい形である。しかしそれは、
**その回線の設定全体を秘密にしてしまう。** MTU も、既定経路を入れるかどうかも、
なぜリンクがその名前なのかも、何一つ見せられなくなる。PPPoE セッションについて
`--dry-run` が見せるべき部分が、まるごと空白になる。

**`passwordfd.so`。** このプラグインはパスワードをファイルディスクリプタから読む。
覆えるのはパスワードだけで（アカウント名は依然オプションである）、しかも資格情報を
「何を生成したか」の側から「プロセスをどう起動したか」の側へ動かしてしまう。
考えるべき場所としては、そちらのほうが悪い。

## 決定

**セッションごとにオプションファイルを 2 つ生成し、pppd には両方を渡す。**

- **peer ファイル**は、設定から導かれるオプションをすべて持つ。プラグインと接続先の
  インターフェース、固定したリンク名、MTU と MRU、既定経路とそのメトリック、
  persist と、persist を実際に働かせる LCP エコーである。これはただの設定であり、
  誰でも読めてよく、`--dry-run` はこれをそのまま出し、差分も取る。
- **資格情報ファイル**は `user` と `password` だけを持つ。モード `0600`、
  置くディレクトリは `0700` とし、ADR 0003 の求めるとおり、内容ではなく
  「どこに、どのモードで書かれるか」だけを報告する。
- pppd の起動時には両方を `file` オプションとして渡す。オプションは複数のファイルにまたがって
  積み上がるので、pppd から見えるセッションは 2 つのファイルを合わせたものになる。
- **レンダラーは資格情報ファイルをどちらも開かない。** peer ファイルは設定だけから作り、
  資格情報ファイルの内容は、2 つの値を引数で受け取る別の呼び出しが作る。
  ファイルを読むこと、そして書き終わるまでの間だけ値を持つことは、適用エンジンの仕事である。

どちらも ADR 0011 が挙げるプラットフォームで確認した。Debian 13 の ppp 2.5.2 は
2 つのファイルをまとめて解釈し、有効なオプションの一覧を出し、`user` と `password` の
出どころとして 2 つ目のファイルを挙げる。

## 影響

- `--dry-run` が PPPoE セッションを丸ごと見せられる。適用前に人が見るものはすべて
  「出してよいほうのファイル」に入っており、出せないほうは
  「このパスにこのモードで書く」という 1 行に縮む。
- 資格情報を入れ替えても差分は出ない。peer ファイルが変わらないからである。
  0600 のファイルを 1 つ書き直してセッションを張り直すだけで済む。ADR 0003 が見込んだとおりである。
- アカウント名がパスワードと同じだけ守られる。`pap-secrets` に寄せたどのやり方でも、
  そうはならなかった。
- セッションごとに、書いて・守って・後から回収するファイルが 2 つになる。
  どちらも regied 自身のディレクトリの下にあるので、回収は他の生成物と同じ走査で済む。
- `/etc/ppp/` 以下には一切触らない。他の用途で既に ppp を動かしているホストでも、
  その secrets ファイルと peers はそのまま残る。
