# ADR 0015: 回線のアドレスはルールセットではなく nftables のセットに置く

- 状態: 決定（2026-09-04）。**決定しただけで、実装はされていない。**

> **いまホストに載っているのは、[ADR 0013](0013-nftables-ruleset-shape.md) と
> [ADR 0004](0004-apply-model.md) が書いているそのままである。**レンダラは今も回線の
> アドレスを引数で受け取って hairpin のルールに書き込むし、適用には今もリンクを読み直して
> テーブルを描き直す最後のフェーズがあるし、`regied render` は今も `-uplink-address` を
> 受け取る。以下に書かれているものはまだ 1 つも無い。回線ごとのセットも、それを播種する
> ものも、pppd のフックも無い。
>
> この記録が ADR 0013 / 0004 / 0005 に付けた注記は、**これから変えること**を述べたもので
> あって、変わったことではない。この記録が実装されるまでは、それらの記録は書かれている
> とおりに読むこと。

## 背景

ポートフォワードの hairpin 側は、回線が持っているアドレスにマッチしなければならない。
内側のクライアントがサービスの公開名を引くとルーター自身の回線アドレスに辿り着くので、
そのアドレスを名指すルールだけがパケットを付け替えられる
（[ADR 0013](0013-nftables-ruleset-shape.md)）。このアドレスは、ルールセットが依存する
値のうち設定に書けない唯一のものである。ADR 0013 はこれを引数で受け取り、
[ADR 0004](0004-apply-model.md) は適用の最終フェーズとして、リンクを読み直し、適用中に
アドレスが現れていればテーブルを描き直す手順を置いた。

適用エンジンを作ってみて、この形の代償が分かった。

**コールドスタートを拾えない。**プロセスのフェーズが起動したセッションは、最終フェーズが
リンクを読む時点ではまだ発呼していない。`Type=exec` のユニットは pppd が走り出した時点で
戻り、PPPoE の発呼には数秒かかる。立ち上がりつつあるホストでは、ルールセットは hairpin の
ルール抜きで入り、次の適用か、まだ存在しないデーモンが動くまで誰も入れない。ADR 0004 が
発呼を待つことを却下しているのは正しい。事業者側のタイミングで止まる適用は、半端に設定
されたホストを抱える。結果として、ポートフォワードが最も必要な瞬間 —— 再起動の直後 ——
にそれが無い。

**ルールセットを、設定ではないものの関数にしてしまう。**ADR 0013 は、エンジンの冪等性は
ルールセットが設定だけの関数であることに依る、と述べている。アドレスを描き込めばそうでは
なくなる。同じ設定が発呼の前後で違う描画になり、記録したテキストは線の状態で変わり、
ルールセットを比べる場所はすべてそれを知っていなければならない。

**描き直しには「走らせない条件」の規則が要る。**セッションの再起動から数ミリ秒後に
リンクを読めば「無い」と答える。それを描画すれば動いているポートフォワードを外すので、
ADR 0004 は防護を足した。アドレスを持っていた回線が何も答えないなら描き直しは止める、と。
防護は正しく、そしてそれはアドレスがテキストの中にあるから必要になっている。

これらはすべて同じ事実を別の側面から見たものである。**アドレスは実行時の状態であり、
ルールセットはそれを設定として扱っている。**

描き込まずにアドレスへマッチする方法は、ほかに 2 つ検討した。

- `fib daddr type local` は、LAN 側を含めルーターが持つすべてのアドレスにマッチする。
  転送対象ポートでルーターの LAN アドレスに来たクライアントが内側の宛先へ送られる
  ことになり、回線に対するポートフォワードの宣言と違う
- pppd のフックから `regied` を走らせて、アドレス付きで描き直す。アドレスはテキストの
  中に残り、ルールセットの書き手が 2 つになって適用と競合する

## 決定

**ルールセットは回線のアドレスを載せない。回線ごと・ファミリごとに名前付きセットを持ち、
hairpin のルールはそのセットにマッチする。**セットは、設定にある回線すべて ——
PPPoE セッションと DS-Lite トンネル、`egressRef` が名指せる kind —— についてテーブルの中で
宣言する。何かがそこを hairpin するかどうかは問わない。空のセットは何にもマッチしない。
線が落ちている間の hairpin ルールの振る舞いとして、それがまさに正しい。

描画されるテキストは設定だけの関数である。発呼の前後で同じ、一度も発呼していないホスト
でも 10 回張り直したホストでも同じであり、適用が記録し比べるのはこれである。

**アドレスを知った者がセットに入れる。**それをする者は 3 つあり、互いに依存しない。

- **適用**。ファイアウォールのフェーズで、テーブルの直後に、各回線のリンクが持っている
  ものを読んで要素として足す。テーブルの置き換えはセットを空にするので、適用のたびに
  カーネルから播き直す。要素は記録するテキストの一部ではなく、テーブルを当てるかどうかの
  判断に関わらない。dry-run はルールセットの横に「足すことになる要素」として示す
- **pppd**。regied が `/etc/ppp/ip-up.d/` と `/etc/ppp/ip-down.d/` に描画するフック
  経由で、ip-up では pppd から渡されたローカルアドレスを上がったリンクのセットに足し、
  ip-down では消す。リンクはセッションの名で命名される（[ADR 0012](0012-networkd-rendering.md)）
  ので、セット名は pppd がスクリプトに渡すインターフェース名から決まり、1 つのスクリプトが
  すべてのセッションに効く。フックはテーブルの有無にかかわらず成功する。起動時の適用より
  先に上がった線には足す先がまだ無く、直後に適用自身の播種が拾う
- **デーモン**。存在するようになったら、カーネルのアドレスイベントから、すべての回線と
  両ファミリについて。これが一般的な仕組みであり、上の 2 つはデーモン無しでホストを正しく
  保つためのものである

2 つのディレクトリはディストリビューション自身のフックと共有なので、スクリプトには regied の
名前接頭辞と所有マーカーを付ける。`/etc/systemd/system` のユニットと同じである
（[ADR 0009](0009-ownership-boundary.md)）。セッションが 1 つも宣言されなくなったら回収する。

**適用の最終フェーズは無くなる。**描き直すものが無い。ロールバックは前のテーブルの
テキストを戻し、適用と同じやり方でカーネルからセットを播く。

**`regied render` は回線アドレスを受け取らなくなる。**それから描画するものが無い。
描画はホスト無しで完結する。[ADR 0006](0006-dry-run-and-rendering.md) が求めていた
とおりに。

## 帰結

- **コールドスタートは IPv4 について解決する。**ファイアウォールのフェーズでテーブルが
  空のセット付きで入り、プロセスのフェーズで pppd が発呼し、そのフックがセットを埋める。
  PPPoE のポートフォワードは IPv4 のポートフォワードである —— DS-Lite 経由は AFTR が
  変換するので検証が拒否する —— から、存在するのはこの場合である
- **PPPoE リンク上の IPv6 の hairpin はフックが拾わない。**pppd の `ipv6-up` がスクリプトに
  渡すのはリンクローカルであり、グローバルアドレスは networkd 経由で来る。networkd に
  フックは無い。適用時にアドレスが在れば適用の播種が拾い、残りはデーモンが拾う。
  この記録の前と同じ状況が、1 ファミリに狭まって残る
- **新しいアドレスでの張り直しは regied ではなく pppd が扱う。**ip-down が古い要素を消し、
  ip-up が新しい要素を足す。ADR 0004 が張り直し途中のリンクを読まないために置いた防護と、
  ルールセットに手を付けなかったときに適用が出していた注記は、それを担っていたコードごと
  無くなる
- **適用が記録するものは単純になる。**テキストは再び設定だけの関数である。誰かが flush
  したテーブルは引き続き問い合わせが気づき、要素もそれと一緒に播き直される
- **フックは regied がホストに置く 4 つめの成果物**であり、共有ディレクトリに置くものと
  しては 3 つめである。所有の規則は既に述べたものそのままである
- **`nft list ruleset` にはアドレスが見え、dry-run に見える必要はない。**dry-run はこの
  適用が足す要素を示す。いまの答えがあるのは動いているホストであり、ADR 0004 が
  「動いているか」を置いたのと同じ場所である
- **netns テストベッドの参照ルールセットは形が変わる。**hairpin ルールがアドレスを名指して
  いたのが、生成されるものはセットを名指す。検証する振る舞いは同じである
- ADR 0004 の最終フェーズと「描き直しは足すだけ」の規則、および ADR 0013 の
  「引数で受ける」の節は、この記録によって補正される。どちらにも注記を置く
