# ADR 0022: DS-Lite トンネルのローカルアドレスを委譲に追随させる

- 状態: 決定（2026-10-23）
- [ADR 0021](0021-values-derived-from-the-delegated-prefix.md) を前提とする
- [ADR 0011](0011-target-platform.md) と [ADR 0012](0012-networkd-rendering.md) を補正する

## 背景

DS-Lite トンネルは、すべての IPv4 パケットを IPv6 に包み、このホストのローカルアドレスから
送る。事業者がプレフィックスを委譲し、上流インターフェースが自分のグローバルアドレスを
受け取らない回線では、ルーターが持つグローバルアドレスは委譲から切り出したものだけである
—— 典型的には下流サブネットの `::1`。トンネルはそのどれかから送らなければならない。

[`DSLiteTunnel.localAddressFrom`](../spec/kinds.md#dslitetunnel) はまさにこのためのもの
だった。「このインターフェースの IPv6 アドレスをトンネルのローカルアドレスにする」。
そうすればトンネルはプレフィックスの変化に追随する。systemd 257 ではそれができない。
networkd の `[Tunnel]` セクションの `Local=` が取るのは、リテラルか、トンネルを積んでいる
リンクのアドレス（`dhcp4`、`dhcp6`、`slaac`、リンクローカルの 2 つの値）である。委譲
プレフィックスから 1 つ取る値 `dhcp_pd` は systemd 258 で入った（[ADR 0011](0011-target-platform.md)）。
だから regied は `localAddressFrom` を下位リンク自身のアドレスとして描画し、別の
インターフェースを名指していれば警告する（[ADR 0012](0012-networkd-rendering.md)）。
下位リンクがグローバルアドレスを持たない回線では、警告が結果のすべてである。そこで構成は
`localAddress` をリテラルで書く —— そしてプレフィックスが変わったときにルーターの IPv4 を
止めたのが、そのリテラルである。

この障害は、書いておく価値のある形で沈黙する。カーネルは、どのリンクも持っていない
ローカルアドレスの `ip6tnl` リンクを上げたままにする。パケットはすべて捨てられ、カーネルの
ログに 1 行出るだけで、他には何も起きない。リンクは上がり、経路はあり、宣言とホストは
一致し、どのターンも収束済みと報告する。

## 決定

### フィールドの意味は保ち、257 では regied がアドレスを渡す

**`localAddressFrom.interfaceRef` は、自分の IPv6 アドレスを 1 つだけ宣言している任意の
`Interface` を名指してよい。systemd 257 では、regied がそのアドレスをリテラルとして
`Local=` に書く。**アドレスは、そのインターフェースの宣言から得られるものである。

| 名指したインターフェースの IPv6 アドレス | `Local=` に入るもの |
|---|---|
| いまと同じく下位リンクそのもの | いまと同じく `slaac` か `dhcp6`。変わらない |
| `fromDelegatedPrefix` | いまの委譲から解決したアドレス（[ADR 0021](0021-values-derived-from-the-delegated-prefix.md)） |
| リテラル | そのリテラル |

IPv6 アドレスを持たないインターフェース、2 つ以上持つインターフェース、
`fromRouterAdvertisement` を持つインターフェースを名指すのは検証エラーである。最初の 2 つは
選択を述べておらず、3 つ目はルーターではないホストであり、自分の DS-Lite トンネルを使う
ことは無い。ADR 0012 がこのフィールドについて挙げている描画時の警告は無くなる。別の
インターフェースを名指せば、いまは言ったとおりに動くからである。

**フィールドは増やさない。**スキーマは既に正しいこと —— *このインターフェースのアドレス*
—— を言っており、それが networkd のどの値になるかはバックエンドのものだと ADR 0011 が
述べた。変わるのは、このプラットフォームでのバックエンドの答えが、networkd が名指す値では
なく regied が計算する値になることである。記載例の宣言は、自分のサブネットの `::1` を持つ
下流インターフェースを名指し、`localAddress` を外す。

もう 1 つの形は、トンネル自身に `fromDelegatedPrefix` を書くことだった。それだと、その
アドレスを既に持っているインターフェースの隣で、サブネットとトークンをもう一度述べることに
なる。1 つのアドレスを 2 回述べることこそ、この記録が取り除くためにあるずれである。

### アドレスが変わったら、トンネルにそれを持たせる

解決したアドレスは `.netdev` に入るので、プレフィックスが変わればそのファイルが書き直され、
ターンは networkd を reload する。networkd 257 が、変わった `Local=` を自分が作る `ip6tnl`
リンクだけでなく既に在るものにも当てるかどうかは、最初の実装単位がテストベッドで確かめる。
networkd の reload は netdev についての自分の記録を置き換えるが、それだけではカーネルの
リンクが変わったとは言えない。

**当てないなら、regied はトンネルのリンクを取り除き、新しいファイルから networkd に作り
直させる。**それはリンクを落とすことであり、無人のターンは上がっているものを落としては
ならない（[ADR 0016](0016-converging-on-the-accepted-declaration.md)）。規則は破るのではなく
狭める。**無人のターンは、いまのローカルアドレスをホストのどのリンクも持っていない
トンネルを作り直してよい。**そういうトンネルは何も運んでいない —— 渡されたパケットは
すべてカーネルが捨てる —— ので、作り直しても上がっていたものは何も落ちない。ローカル
アドレスがまだ持たれているトンネルは、これまでどおり、無人のターンは手を付けず、提出
されたターンが作り直す。

### 委譲が無い間

トンネルは、値が無ければ存在できない成果物である
（[ADR 0021](0021-values-derived-from-the-delegated-prefix.md)）。委譲が無ければ、ターンは
トンネルのファイルをそのままにして待ち、インターフェースを名指す。起動したばかりの
ホストでは、委譲が届くまで前のトンネルが前のアドレスのまま在る。プレフィックスが同じで
戻ってきたなら、それは一度も間違っていなかった。

### systemd 258 では

`Local=dhcp_pd` が *別のリンクのアドレス* —— 下流インターフェースのもの —— を表せるのか、
トンネルを積んでいるリンクに割り当てられた委譲のアドレスしか表せないのかは、258 が
プラットフォームに来たときに確かめる。後者なら、regied が書くリテラルは一時しのぎでは
なく正しい描画のままである。宣言が名指すアドレスであり、その周りにライフサイクルは
作っていない。

## 採らなかった選択肢

**上流インターフェースにも委譲のアドレスを割り当てる。**そうすれば既存の `slaac` /
`dhcp6` の描画がアドレスを見つける。networkd 257 は委譲されたサブネットを上流のリンクに
割り当てられるが、そのアドレスが取るサブネットを regied が予約しなければならなくなり、
下位リンク自身のアドレスは networkd が複数の中から選ぶ。アドレスを名指すのではなく、
問題を移すだけである。

**プレフィックスが変わったときにトンネルを書き直す、pppd 風のフックや networkd の
dispatcher スクリプト。**ADR 0015 が 2 つ目の書き手に反対して挙げた理由で退ける。ターンと
競合し、描画の外でアドレスを計算する唯一の場所になる。

**トンネルを監視し、通信が止まったら作り直す。**それは健全性であって差ではない
（[ADR 0016](0016-converging-on-the-accepted-declaration.md)）。
[ADR 0026](0026-no-uplink-failover-inside-regied.md) を見よ。

## 帰結

- **プレフィックスが変わっても、ルーターの IPv4 が落ちるのは**、アドレスイベントに続く
  ターンと、networkd の reload または作り直しの間だけになる。
- **`localAddress` は静的にアドレスを持つ回線のために残る。**委譲のある構成がそれを使う
  理由は無い。
- **無人のターンに、狭く定義した作り直しが 1 つ加わる。**ホストがもう持っていない
  ローカルアドレスのトンネルである。コードが入るときに段の表に書く。
- `--dry-run` は、AFTR のアドレスを既に見せているのと同じように、解決したローカル
  アドレスを見せる。

## 実装単位

[ADR 0021](0021-values-derived-from-the-delegated-prefix.md) の単位 1 と 2 を、1 つの
pull request で。委譲を読み、解決し、その最初の消費者としてこのフィールドを扱う。spec の
`DSLiteTunnel` の節と、ADR 0011 と ADR 0012 の注記は、同じ pull request で直す。reload で
既存のリンクの `Local=` が変わるかどうかのテストベッドでの確認が、作り直しを作るかどうかを
決める。
