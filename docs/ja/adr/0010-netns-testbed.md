# ADR 0010: 擬似 WAN のテストベッドは network namespace で組み、被試験体を差し替えられる形にする

- 状態: 決定（2026-08-23）

## 背景

ルーターについて知りたいのは、設定が読めるかどうかではない。実際にパケットが通るか
である。送信元レンジごとに 2 本の出口を使い分け、外から内へポートフォワードを通し、
内から自分のグローバル宛にも同じ経路を通し、それ以外の外からの通信は落とす。
設定ファイルを読んでも、このどれも分からない。

答えの形は 3 つの制約で決まった。

**対象の機器が手元に無い。** regied を動かすことになる arm64 の SBC はまだ無く、
稼働中のルーターは試験に使えない。**回線が 1 本しかなく、ルーターを止められない構成**
を想定している。

**被試験体が決まっていなかった。** テストベッドを作った時点では、regied を書くのか
既存の実装を採るのかがまだ開いていた。特定の実装に依存したテストベッドは、
どちらを選ぶかの判断には使えない。

**開発機に道具を入れられない。** 開発は `nft` / `dnsmasq` / `pppd` / `pppoe-server` の
入っていないコンテナの中で行っており、ホストにもそのコンテナにも何も入れない方針である。

## 決定

network namespace で擬似 WAN を組み、その中で被試験体を動かす。

### トポロジ

```
[client] --- [router（被試験体）] --- [wan] --- [internet]
                                        |
                          PPPoE サーバー / DS-Lite の AFTR
```

| netns | 役割 |
|---|---|
| `rg-client` | LAN 側の端末。送信元アドレスを 3 つ持ち、PBR のレンジをまたぐ |
| `rg-router` | 被試験体。LAN 側と WAN 側のインターフェースだけが入った状態で渡される |
| `rg-wan` | 回線提供側。PPPoE サーバーと DS-Lite の AFTR を兼ねる |
| `rg-internet` | 到達確認用のサーバーを置く。アドレスを 2 つ持つ |

DS-Lite は IPv6 到達性の上に ipip6 を張り、AFTR 側で終端して NAT44 する。
B4（ルーター）側では NAT しない。実際の DS-Lite と同じ役割分担である。

アドレスはすべて文書用に予約されたレンジ（RFC 5737 / RFC 3849）から取る。

### 検証は外側からの観測だけで行う

7 項目の判定はすべて `rg-client` と `rg-internet` から行い、被試験体の中を覗かない。
ルーターの経路表や nftables の中身を確かめるテストは、その実装にしか通用しないため
書かない。

**どちらの経路を通ったかは「外から見えた送信元アドレス」で判別する。**
PPPoE で払い出されるアドレスと、AFTR が NAT44 に使うアドレスを別にしてあるので、
到達確認用のサーバーが接続元を一行返すだけで、経路も NAT も外部ポートも分かる。
「繋がるか」では経路を区別できない。

### 被試験体は差し替えられる

ルーターを組み立てる処理は 1 つのスクリプトに閉じ込め、環境変数
`REGIED_NETNS_ROUTER_SETUP` で差し替える。受け渡しは次のとおり。

| 項目 | 約束 |
|---|---|
| 呼ばれ方 | 引数 `up` で組み立て、`down` で後始末。`up` は疎通が成立してから返る |
| 渡されるもの | `rg-router` の中に LAN 側と WAN 側のインターフェースが 1 本ずつ入った状態 |
| トポロジの値 | アドレス・レンジ・ポート・MTU は共有定義から環境変数で渡す |
| 認証情報 | PPPoE のユーザー ID とパスワードはファイルのパスとして渡す。値では渡さない |
| 期待される結果 | 7 項目が外側から観測できる状態 |

既定の被試験体は、手書きの `ip` と `nft` で組んだ参照実装である。まずテストベッド
自身が 7 項目を判定できることを、この参照実装で証明する。ほかの実装を掛けるときは、
上の約束を満たすスクリプトを 1 本書いて差し替える。テストは変えない。

認証情報をファイル経由に限ったのは、テストの都合ではない。設定に秘密情報を直接
書けるようにしないという方針を、被試験体との境界でも緩めないためである。

### 「落ちた」と「待ち受けが無い」は時間で区別する

繋がらないことだけを見ると、フィルタが落としたのか、単に何も動いていないのかを
区別できない。何も動いていない状態が合格になるテストは、検証として意味がない。

落としているなら接続要求は時間切れになり、落としていないならルーターが RST を返して
即座に拒否される。この差を所要時間と失敗の内容で判定する。

### 実行は特権の兄弟コンテナに閉じ込める

道具は専用のイメージにだけ置き、`--privileged` の兄弟コンテナとして起動する。
ホストにも開発コンテナにも何も入れない。PPPoE はカーネルモジュールなので、
実行時に `/lib/modules` を読み取り専用で渡し、コンテナの中から読み込む。

テストは build tag `netns` の後ろに置き、`go test ./...` が拾わないようにする。
`make test-netns` は道具が揃った環境で直接走り、`make test-netns-docker` が
コンテナを用意して同じものを呼ぶ。飛ばしたものが通ったように見えてはならない。

**2026-08-31 追記。** 最後の 1 文が、書いたとおりには成り立っていなかった。飛ばすときに
理由は標準エラーに出していたが、**`go test` はパッケージが通ったときの出力を捨てて `ok` と
だけ表示する。** 走っていない実行が緑に見えていた。実際に、root の PATH に `nft` が無い
Debian のホストで成功と報告された。**このスイートを呼ぶこと自体を「道具が揃っているはず」
という表明として扱う。** make のターゲットはコンテナイメージと同じ変数を立てるようにし、
前提が欠けていれば理由を述べて失敗する。`go test -tags netns` を素で叩いた場合は従来どおり飛ばす。

## 結果

テストベッドが、試験する対象より先に手に入る。候補となる実装を同じ 7 項目で測れるし、
実機が出来た後も、設定を変えるたびに投入前にここを通せる。

テストを書いた後、わざと壊した被試験体を通して 7 項目それぞれが本当に落ちることを
確認した。落ちないテストは、通っても何も言っていない。

差し替え点は実際に使った。外部の実装を、被試験体側のスクリプトを 1 本足すだけで
掛けられた。テスト側は 1 行も変えていない。

**環境差で結果が変わったことがある。** Docker（Debian bookworm / kernel 6.8）では
7 項目とも通るのに、仮想マシン（Ubuntu 26.04 / kernel 7.0）では NAT のマッピングの
項目だけが再現性をもって落ちた。原因はルーターではなく、応答の受け取り方だった。
socat 1.8 は EOF を伝えるために空のデータグラムを足すため、受け側がそれにも応答し、
同じ観測が 2 つ並んで届く。1 度に 1 行しか来ない前提で読んでいた。

ここは実機に持っていく前の関門であり、環境差で結果が変わっては役目を果たせない。
**外部コマンドの応答は、何回に分かれて届いても同じ判定になる形で読む。**
その読み取りは build tag の外に出し、ユニットテストで押さえてある。検証は Docker と
仮想マシンの両方で行う。

擬似 WAN で確かめられないことも残る。

- **カーネルの差** — 検証は amd64 の開発用カーネルで行う。対象は arm64 の
  vendor kernel であり、同じではない
- **回線側の振る舞い** — PPPoE で払い出されるアドレスは固定してある。再接続や
  アドレス変更、AFTR の実装差は再現していない
- **IPv6 の取得経路** — 実回線が RA と DHCPv6-PD で得るものを、ここでは固定で
  置いている。プレフィックスの受信と配布は検証していない
- **DHCP と DNS** — dnsmasq の領域は 7 項目に含まれていない。イメージには入れて
  あるので、必要になった時点で足せる

## 検討した選択肢

**Docker の network を入れ子にする。** ルーターをコンテナとして動かし、Docker の
ネットワークで繋ぐ案。PPPoE と ipip6 のために結局は特権が要るうえ、netns を直接
扱うより間接的で、経路表や tunnel の状態を確かめにくい。

**仮想マシンで組む。** 実機に近いが、起動が遅く、被試験体の差し替えに時間がかかる。
判断の道具としては重い。

**実機が出来るまで待つ。** 移行の当日に初めて動かすものは、当日に初めて問題が分かる。
先に確かめられるものを後回しにする理由がない。
