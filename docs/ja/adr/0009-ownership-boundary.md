# ADR 0009: 宣言したものだけを所有する

- 状態: 決定（2026-08-23）

## 背景

regied は他の書き手と同じホストを共有する。

- **systemd-networkd と netplan** — ADR 0008 のとおり、regied は networkd に設定を渡す。
  ノードでは netplan が base のネットワークを持ったままになる
- **BGP デーモン** — 将来 MetalLB を BGP 化すると、FRR / BIRD が学習した経路を
  カーネルのルーティングテーブルに入れる。regied はそれを宣言していない
- **kube-proxy / Cilium / Calico / Docker** — ルーター以外のノードに regied を持ち込む場合、
  そこには大量の nftables / iptables 状態が既にある

適用が「宣言どおりにして、それ以外は消す」形だと、**BGP が入れた経路を毎回消し飛ばし、
ノードではクラスタのネットワークを壊す。**

## 決定

**自分が宣言したものだけを所有し、所有していないものには触らない。**

- nftables は **自分のテーブルだけ**を作り替える。ルールセット全体を flush しない
- ルーティングテーブルは、自分が入れた経路だけを消す。学習経路や他者の経路を消さない
- 生成物には所有を示す印を付け、印のあるものだけを回収の対象にする
- networkd の設定ファイルは自分の接頭辞を持つファイルとして置き、他人のファイルを書き換えない

## 帰結

- MetalLB の BGP 化は、`BGPPeer` 相当の kind と設定生成を足すだけで載る。
  学習経路と衝突しない。ポリシールーティングは、プールを含む CIDR を静的に指しておけば
  VIP の増減で触る必要がない（**動的なポリシールーティングは要らない**）
- ルーター以外のノードのファイアウォールを regied で書けるようになる。
  base のネットワークに触らないため、クラスタを壊さない
- ただし **配布は regied の仕事ではない。** regied は 1 ノードを見るデーモンであり、
  設定ファイルをどう配るかは別の仕組み（fleet-infra など）が持つ。
  ここを曖昧にすると、多ノード管理へ滑り落ちる
- ファイアウォールのモデルは、`wan` / `lan` を固有名詞として型に埋めない。
  hook（input / forward / output）とインターフェース集合を素にし、
  `wan` や `lan` は集合の名前にすぎない形にする。そうしないとノードに持ち込めない
