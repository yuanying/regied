# ADR 0011: Debian 13 の上に載せる

- 状態: 決定（2026-08-31）

## 背景

[ADR 0008](0008-delegate-to-existing-implementations.md) で systemd-networkd に渡す層を
決めたが、7 領域の実測は Ubuntu 26.04 で取ったものだった。ルーターは Debian 13
（trixie）で組む。実測を、実際に動かすプラットフォームの上で言い直す必要がある。

委譲先（systemd-networkd、dnsmasq、pppd、nftables）はどれも trixie の main にある。
委譲するという判断自体はディストリビューションが変わっても生き残る。書き留めておく
価値のある違いが 3 つある。

**netplan が居ない。** ADR 0008 は netplan を経由しない理由を長く書いており、
[ADR 0009](0009-ownership-boundary.md) は汎用ホストで base のネットワークを持ち続ける
別の書き手として netplan を名指している。Debian ではどちらも当てはまらない。
`/etc/systemd/network/` は最初から書き手が 1 つで、所有の境界はむしろ易しくなる。

**networkd は既定で有効ではない。** Debian の導入直後、ネットワークは ifupdown が
（デスクトップ構成なら NetworkManager が）持っている。Ubuntu server が networkd を
動かした状態で立ち上がるのに対し、Debian には明示的に切り替えを指示する必要がある。

**当てにしていた指定が 1 つまだ無い。** ADR 0008 の表は `[Tunnel]` の `Local=` が
`dhcp_pd` を取れると記録している。DS-Lite のトンネルが委譲されたプレフィックスから
自分の端点アドレスを取る書き方である。この値が入ったのは systemd 258 だった。
trixie は 257 であり、trixie-backports にも systemd は無い。よってこの環境では
`Local=` は下位リンク側のアドレス、すなわち `dhcp6` か `slaac` を取る。

## 決定

**Debian 13（trixie）を、regied を作り・試験し・投入するプラットフォームとする。**

ディストリビューションのパッケージとして、あることを前提にするもの。

| 前提にするもの | 何に使うか |
|---|---|
| systemd 257 以降、`systemd-networkd` が有効であること | リンク、アドレス、ルート、ポリシールール、ip6tnl トンネル、プレフィックス委譲、ルーター広告 |
| `dnsmasq` | DHCP サーバーと条件付き DNS フォワード |
| `ppp` | PPPoE の回線 |
| `nftables` | ファイアウォール、NAT、ポリシールーティングのマークを打つ側 |

ルーターのリンクを他の何かに持たせない。`/etc/network/interfaces` は空にし、
NetworkManager は入れない。これは運用側が満たす前提であって、regied がやることでは
ない（[範囲](../scope.md)）。

regied が生成する networkd の指定、すなわち「systemd 257」の根拠は次の 4 つである。
`Mode=ipip6` の `Kind=ip6tnl`、`[DHCPPrefixDelegation]` の `SubnetId=` と `Token=`、
`IPv6SendRA=`、ルーティングポリシールールの `FirewallMark=`。いずれも 257 にある。

したがって `DSLiteTunnel.localAddressFrom` は、委譲されたプレフィックスから取った
アドレスではなく、下位リンク自身のグローバルアドレス（`slaac` または `dhcp6`）に
落ちる。スキーマは変わらない。もともと*そのインターフェースの IPv6 アドレス*と
書いてあり、それが networkd のどの特別値になるかはバックエンドの領分である。

## 帰結

- テストベッドのコンテナと投入先が同じディストリビューションになる。ADR 0010 は
  bookworm のコンテナと Ubuntu 26.04 の仮想マシンで結果が割れたことを記録している。
  両者の違う軸が少ないほど、テストベッドの緑が嘘をつく余地が小さくなる。
  移した時点で違いが 1 つ出た。ppp 2.5.2 と pppoe 4.0 では、テストベッドの PPPoE サーバー
  がカーネルモードで LCP を終えられない。ユーザー空間で動かすようにした。7 項目とも
  Debian 13 で通っている。
- ADR 0008 と ADR 0009 にある「netplan」は「そのホストで base のネットワークを持って
  いるもの」と読むこと。論旨はそれがどの道具かに依存していないし、Debian のルーターで
  はそれが何も居ないという話になる。
- トンネルの端点アドレスを委譲プレフィックスから導く必要のある構成は、systemd 258 が
  この環境に届くまで表現できない。それが「そろっていると気持ちがよい」ではなく本当に
  必要だと分かったなら、プラットフォームを見直す理由にはなるが、アドレスの寿命管理を
  自前で持つ理由にはならない。それこそ ADR 0008 が引き受けないと決めたものである。
- プラットフォームを名指すのは、何があることを前提にするかを言うことである。regied が
  それらを導入・更新・構築するようになるわけではない。そこは範囲の外のままである。
