# ADR 0020: ポートフォワードの戻りを、届いた回線に戻す

- 状態: 決定（2026-09-13）
- [ADR 0013](0013-nftables-ruleset-shape.md) を補正する

## 背景

`PortForward` は接続が届く回線を名指す。答えるのは内側のホストで、その戻りの経路は
そのホストの送信元アドレスで決まる。逆方向の変換で送信元が回線のアドレスに戻るのは
経路決定の後だからである。回線が 1 本のホストでは経路は main テーブルであり、言うことは
無い。2 本のホストでは、変換先のアドレスを覆う `EgressRoutePolicy` が戻りにマークを
打ち、その政策が名指す回線から送り出す。それは変換先自身のトラフィックが出ていく
回線であって、接続が届いた回線とは限らない。変換は起き、パケットは変換先に届き、戻りは
別の回線から出て、接続は成立しない。設定のどこも間違って見えない。

[ADR 0013](0013-nftables-ruleset-shape.md) はこれを記録し、スキーマ側に預けた。直すには
回線ごとのマークが要るが、スキーマが導出するのは政策ごとのマークで、1 つの回線を複数の
政策が名指しうる、という理由である。これまでの回避策は、すべてのフォワードの変換先を、
そのフォワードの回線に送る政策のレンジの内側に置いておくことだった。これは動く。そして
手で真に保ち続けなければならない構造である。フォワードとアドレスのレンジという 2 か所が
一致していなければならない。レンジの外のホストへフォワードを足すと、届くのに答えない
サービスができ、外からの到達確認ではそれが見えない。検証はこれを警告していたが、結合を
表に出しただけで、消してはいなかった。

欠けている事実を、カーネルは既に持っている。接続追跡は、接続の最初のパケットが回線に
届くのを見ている。**接続マーク**はそれをパケットではなく接続に持たせられる。このマークは
アドレスから導いたものではなく接続に付いているので、逆方向の変換をくぐっても残る。
それを負った戻りは、どの政策が送信元アドレスを見るよりも先に、マークで経路を決められる。

形は 2 つ考えた。

- **`PortForward` に畳む。** フォワードは公開する回線を既に名指している。フォワードが
  書き換えた接続すべてにその回線を覚えさせ、戻りで復元するのに、リソースがまだ言って
  いないことは何も要らない。
- **`EgressRoutePolicy` に新しい種類を足す。**「接続が届いた回線から返す」と書く政策で
  ある。汎用ではあるが、書き忘れられる。フォワードを書いて政策を書かなかったホストは
  今日とまったく同じ壊れ方をし、揃えるべき 2 か所も同じまま残る。

## 決定

**`PortForward` は戻りを公開した回線に戻し、そのために宣言するものは無い。**
仕組みは 3 つの部分からなる。

### 回線とファミリの組ごとに、マーク 1 つとテーブル 1 つ

`PortForward` が 1 つでも公開されている回線とアドレスファミリの組ごとに、regied は
ルーティングテーブル 1 つとファイアウォールマーク 1 つを導出する。割り当てるのは
`EgressRoutePolicy` と同じ allocator で、政策の後ろである。固定された政策の値、次に
固定されていない政策を評価順に、次に回線をファミリと名前の順に。固定された値は割り当て
の前に予約されるので、両者は衝突しない。回線の組は固定できない。regied の外がそれに
依存すべきではなく、そのためのフィールドは足さない（[ADR 0002](0002-configuration-schema.md)）。

同じ回線への政策のテーブルとは共有しない。どちらも同じデフォルトルートしか持たなくても
である。共有すれば戻り経路が、消されうる政策に結び付く。それはこの記録が消そうとして
いる結合そのものである。フォワードの戻り経路は、たまたまその回線を名指した政策がすべて
消えても残る。

この組は、ホストに `EgressRoutePolicy` が 1 つも無くても導出する。回線が 1 本のホストでは
何も変わらず（テーブルのデフォルトルートは main テーブルのそれと同じ）、規則が文書の
他の何かに条件付きで依存することを防ぐ。

### マークチェーンの先頭に、2 種類の規則

`prerouting_mark` は ADR 0013 が置いたとおり、nat prerouting の後ろ、priority `filter` で
走る。どの政策の規則よりも前に、次を持つ。

1. **復元の規則が 1 本。** マークを負った接続の、reply 方向のパケットに、接続のマークを
   写し、チェーンから return する。return するので、後ろの政策はこの戻りに触れない。
   LAN 全体を覆う政策があれば、それが戻りに自分の回線のマークを打ってしまうところで
   ある。接続のマークがどの送信元一致よりも優先される。

   一致させるのは reply 方向だけである。元方向（外から届き、内側のホストへ書き換えられた
   パケット）が回線のマークを負ってはならない。回線のテーブルにあるのはデフォルトルート
   だけで、それで経路を決めたパケットは外へ送り返される。ADR 0013 が LAN の経路をすべての
   テーブルに写す案を退けたのはこの理由による。戻りの宛先は外の相手であり、回線の
   デフォルトルートがそれに正しい経路である。

2. **保存の規則が、回線とファミリの組ごとに 1 本。** その回線にそのファミリで届き、
   ポートフォワードが書き換えた（`ct status dnat`）接続の最初のパケットに、回線のマークを
   接続へ書く。DNAT の状態が、対象をポートフォワードに限る。ホスト自身宛ての接続には
   マークを付けない。この規則は return しない。パケットはそのまま政策へ進み、外の送信元は
   今日と同じく何にも一致しない。

チェーンは `PortForward` があれば、政策の有無にかかわらず存在する。

### テーブルと規則は回線に置く

回線の `.network` ファイルに、導出したテーブルのデフォルトルートと、導出したマークで
そのテーブルを選ぶ `[RoutingPolicyRule]` が加わる。書き方は政策のそれと同じである
（[ADR 0012](0012-networkd-rendering.md)）。静的経路も政策も無いが公開に使われている
PPPoE セッションは、これだけのためにファイルを得る。

`sourceValidation` に新しい規則は要らない。戻りは LAN のリンクから LAN の送信元アドレスで
入り、main テーブルにはそこへ戻る経路がある。strict の逆経路フィルタが確かめるのは
それである。

### 範囲外のもの

**ホスト自身宛ての接続は扱わない。** その戻りは output フックで生成され、送信元は回線
自身のアドレスである。これは別の事情である。アドレスは既に回線のものであり、main
テーブルがそれを正しいリンクから出すかどうかは、ホストのデフォルトルートの問題であって
フォワードの問題ではない。ホスト自身の戻りを固定する必要が出たなら、それは output
チェーンの復元規則であり、別の決定になる。

**ヘアピンは変わらない。** 内側から回線のアドレスへ繋ぐ接続は LAN のリンクから届くので、
保存の規則はそれを見ず、接続はマークを負わない。その戻りは復元の規則に一致せず、政策の
ローカル除外とヘアピンの送信元変換によって内側に留まる。ADR 0013 と
[ADR 0015](0015-uplink-addresses-in-sets.md) が作ったとおりである。

## 帰結

- **フォワードの変換先が、政策のレンジの内側にある必要は無くなった。** そう言っていた
  検証の警告は消し、それが立っていた前提も消す。戻りは答えるホストの送信元アドレスで
  経路が決まる、という前提は、regied が扱う戻りにはもう当てはまらない。
  `config/example.yaml` は変換先について、以前と逆のことを言う。
- **変換先自身の外向きトラフィックは影響を受けない。** マークを保存するのは回線に届いた
  接続だけで、他には保存しない。フォワードを動かすためだけに政策のレンジの内側に
  置かれていたホストは、同じセグメントの他のホストと同じ回線から出られるようになる。
  それ自身の理由で公開した回線から出るべきホストは、これまでどおり `EgressRoutePolicy`
  でそう書く。
- **このルールセットが入る前に成立していた接続は、マークを負っていない。** その戻りは
  従来どおり送信元アドレスで経路が決まる。戻りを回線に留めるのを政策に頼っていた
  ホストで、同じ変更でその政策を消すと、そうした接続は切れる。その変更をする運用者は
  それを見込むこと。それ以降は、政策の変更が成立済みの接続を動かさない。マークは
  パケットではなく接続に付いているからである。
- **従来の書き方の宣言は、そのまま動く。** 変換先のレンジをフォワードの回線に送る政策が
  残っていても、戻りは先に復元されて return し、政策はそれを見ない。変換先自身の
  トラフィックは政策に従う。どちらの半分も結果は同じなので、政策は後で消しても残しても
  よい。
- **番号は動く。** 回線の組は政策の後ろに割り当てるので、政策を消せばその後ろが
  ずれる。政策を消したときにいつも起きていたことと同じである。regied の外が値に依存
  すべきではなく、regied の中にもそうした編集をまたいで値が安定することに依存するものは
  無い。
- **netns のテストベッドに、変換先が政策のレンジの外にあるフォワードが加わり**、外から
  届くこと、ヘアピンすること、変換先自身のトラフィックが引き続きもう一方の回線から出る
  ことを確かめる。参照ルーターも同じ仕組みを持つ。参照は他のすべてと同じく変換の前に
  マークするので、テストベッドがこの検査を判定できることを示せる
  （[ADR 0010](0010-netns-testbed.md)）。
- ADR 0013 の最後の帰結はこの記録で補正され、注記を持つ。
